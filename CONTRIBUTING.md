# Участие в разработке

Проект состоит из инструкций, автономных Bash-скриптов для Ubuntu и Python-скриптов на стандартной библиотеке. Python 3.10 — минимальная версия. Сборки приложения и установки Python-зависимостей нет.

## Проверка изменений

```bash
python3 -m unittest discover -s tests -v
for script in scripts/*.sh; do bash -n "$script"; done
shellcheck --severity=warning scripts/*.sh
gitleaks git --redact --log-opts='--all' .
```

На macOS инструменты доступны через `brew install shellcheck gitleaks pre-commit`. На Ubuntu — ShellCheck и jq через apt; Gitleaks — из официального релиза или контейнера. `pre-commit install` включает проверку добавляемых секретов, `pre-commit run --all-files` проверяет отслеживаемые файлы. Новые файлы сначала внимательно просматривай: проверка истории не видит незакоммиченные изменения.

Linux-тесты серверных скриптов запускаются только при root в тестовой среде, иначе пропускаются. Они перенаправляют записи во временный каталог и подменяют Xray/systemd, сохраняя настоящие jq, tar и файловые операции. Для полного локального прогона:

```bash
docker run --rm -e DEBIAN_FRONTEND=noninteractive \
  -v "$PWD/scripts:/workspace/scripts:ro" \
  -v "$PWD/tests:/workspace/tests:ro" -w /workspace \
  python:3.10-slim bash -c \
  'apt-get update -qq && apt-get install -y -qq jq >/dev/null && python -m unittest discover -s tests -v'
```

В контейнер передаются только исходники и тесты. Не монтируй личные конфиги, `/root`, SSH-ключи или сокет Docker. Серверные установщики нельзя запускать на рабочем компьютере для проверки синтаксиса.

CI выполняет тесты на Ubuntu 22.04 / Python 3.10 и Ubuntu 24.04 / Python 3.12, ShellCheck и сканирование истории Gitleaks. Изменения поведения сопровождай тестом, воспроизводящим проблему; правки инструкций — проверкой команд на одноразовом VPS.

## Pull request

Опиши проблему, итоговое поведение и реально выполненные проверки. Используй синтетические адреса (`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`, `example.com`) и явные плейсхолдеры вместо рабочих ключей. Не прикладывай полный вывод конфигураций и архивы с сервера.

Не добавляй зависимость или фреймворк без практической необходимости. Сохраняй совместимость с Ubuntu 22.04 и Python 3.10. При изменении команд обновляй README, основной гайд и соответствующий раздел дополнительных возможностей.

## Ошибки и уязвимости

В обычном issue достаточно версии ОС, Xray и клиента, шагов воспроизведения, ожидаемого поведения и обезличенной ошибки. Для уязвимостей используй порядок из [SECURITY.md](SECURITY.md).
